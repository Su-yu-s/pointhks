# LitePT ScanNet200 实例分割与 RANSAC 测量设计

日期：2026-09-08

## 1. 目标

先在 WSL Ubuntu 中独立跑通 LitePT ScanNet200 实例分割，再把稳定输出接入 Windows Qt/C++/PCL 桌面端。LitePT 负责判断点的语义类别并区分对象实例；RANSAC 只处理用户选中的单个实例，负责精确拟合几何形状和计算尺寸。

第一阶段不修改 GUI，避免在模型输入、依赖和输出尚未验证时扩大调试范围。

## 2. 范围

### 第一阶段：独立实例分割

- 安装并验证 `google-sparsehash` 与 `pointgroup_ops`。
- 使用现有 ScanNet200 LitePT-S 实例分割权重。
- 新增一个面向自定义点云的推理入口。
- 支持读取带 XYZ、RGB 的 PLY/PCD；如果没有法向量，由预处理模块估计法向量。
- 输出逐点语义类别、实例编号和置信度，并生成可视化点云及实例摘要。
- 记录推理耗时、峰值显存、输入点数和实例数量。

### 第二阶段：Qt/C++ 集成

- GUI 通过文件和命令调用 WSL 推理脚本。
- 后台执行推理，避免阻塞界面。
- 读取逐点结果并按语义或实例着色。
- 在对象树中显示类别、实例编号、点数和置信度。
- 用户选中一个实例后，将该实例点集交给现有 RANSAC 模块。
- 根据目标形状执行平面、直线、圆柱、包围盒或轮廓拟合，并导出尺寸。

以下内容不属于当前实现范围：模型训练、建筑专用类别扩展、瓷砖逐块识别、自动生成施工报价，以及无需人工复核的工程级测量。

## 3. 输入约束

ScanNet200 权重按室内 RGB 点云训练，模型输入特征为颜色和法向量，共 6 个通道。输入点云应满足：

- 必须包含 XYZ 坐标。
- 应包含真实 RGB 颜色。
- 法向量可以由文件提供，也可以在推理前估计。
- 坐标单位必须由用户或文件格式明确指定；内部统一按米处理。
- 每个预处理后的点必须保留到原始点的索引映射。

只有 XYZ 的 `testdata1.pcd` 可用于验证文件读取、索引映射和 RANSAC，但不得用于评价 ScanNet200 识别质量，也不得通过填充伪颜色生成看似可信的识别结果。

## 4. 组件设计

### 4.1 点云读取器

职责：读取 PLY/PCD，检查字段、数值范围和坐标单位，输出统一的数据结构。

统一结构包含：

- `coord`: N×3 浮点坐标。
- `color`: N×3 颜色，内部归一化到模型要求的范围。
- `normal`: N×3 法向量。
- `source_index`: N 个原始点索引。

输入缺少 RGB 时立即给出明确错误；输入缺少法向量时进入法向估计。

### 4.2 预处理器

职责：检查 NaN/Inf、估计法向量、自动判断输入上方向并统一到 Z-up、执行体素采样、构建模型输入，并维护索引映射。默认剔除无效点，但 `point_labels.bin` 仍按原始点数写回；无效点使用 `semantic_id=-1`、`instance_id=-1`、`confidence=0`。严格调试时可选择遇到无效点立即失败。

默认先采用与配置一致的体素参数。大点云发生显存不足时才启用空间分块，并在重叠区域通过置信度合并结果。分块不是首版默认路径，以免过早引入边界合并问题。

### 4.3 LitePT 实例推理器

职责：按原项目配置构建完整的 ScanNet200 实例分割模型，严格加载 checkpoint，运行语义预测和 PointGroup 实例聚类。

启动时检查：

- CUDA 是否可用。
- checkpoint 与模型结构是否完全匹配。
- `pointgroup_ops` 和 sparsehash 是否可导入。
- 输入特征维数是否为 6。

模型输出必须经过结构检查，不允许静默忽略缺失权重或用随机初始化层继续推理。

### 4.4 结果映射与导出器

职责：把采样点预测映射回原始点，并输出稳定、可供 C++ 读取的接口文件。

输出目录包含：

- `labeled_cloud.ply`：按实例着色的点云。
- `point_labels.bin`：定长二进制逐点结果，按原始点顺序存储。
- `source_index.bin`：有效点到原始点的索引映射。
- `instances/instance_NNN_class.ply`：可直接交给几何测量器的独立实例点云。
- `instances.json`：实例摘要，包括类别、实例编号、点数、平均置信度和包围盒。
- `run.json`：输入路径、权重版本、参数、耗时、显存和错误信息。

`point_labels.bin` 每点记录固定为：`int32 semantic_id`、`int32 instance_id`、`float32 confidence`。未归入任何有效实例的点使用 `instance_id = -1`。

### 4.5 Qt/C++ 桥接器

职责：将当前点云导出为约定输入文件，调用 WSL 命令，监控进程，读取输出并校验点数。

只有当输出点数与提交给推理器的原始点数一致时，GUI 才应用标签。调用失败、进程中止或结果不完整时，保留当前点云状态并显示错误，不覆盖已有结果。

### 4.6 几何测量器

职责：只对选中的实例点集做精确几何处理。

- 平面目标：RANSAC 平面拟合，再投影到平面坐标系中提取轮廓、边线和矩形尺寸。
- 线性或圆柱目标：使用对应的 RANSAC 模型。
- 不规则目标：使用 OBB、凸包或网格轮廓，不强制套用平面模型。
- 所有尺寸同时输出数值、单位、内点比例和残差，供人工判断结果是否可靠。

## 5. 数据流

1. 用户在 Qt GUI 中加载点云。
2. GUI 检查 XYZ/RGB 和单位，并将点云写入临时交换目录。
3. GUI 后台调用 WSL 中的实例分割脚本。
4. Python 读取点云、估计法向、构建特征并执行 LitePT 推理。
5. Python 将标签映射回原始点，原子化写入结果目录。
6. GUI 校验运行状态、点数和文件版本，然后按实例着色并更新对象树。
7. 用户选择一个实例。
8. GUI 将该实例点集送入几何测量器。
9. RANSAC 或包围盒/轮廓算法输出精确几何参数和尺寸。

## 6. 错误处理

- 缺少 RGB：拒绝正式推理，并说明该权重需要真实颜色。
- 缺少法向量：自动估计；估计失败则终止并指出异常点比例。
- checkpoint 不匹配：终止，不使用非严格加载绕过。
- CUDA 或扩展不可用：启动前失败并给出具体依赖名。
- GPU 显存不足：记录失败点数和显存；后续允许用户启用分块模式重试。
- 输出点数不一致：GUI 拒绝加载结果。
- 低置信度实例：保留显示但标记为低可信，不自动进入测量。
- 测量残差过大：显示拟合失败或低可信，不输出“精确尺寸”的结论。

## 7. 测试与验收

### 第一阶段验收

1. 环境测试：`pointgroup_ops`、sparsehash、CUDA 和 checkpoint 均通过启动检查。
2. 输入测试：正确读取一份真实 RGB 室内点云；缺 RGB 的点云得到明确拒绝信息。
3. 推理测试：在 RTX 4060 Laptop 8GB 上至少成功完成一份样本推理。
4. 输出测试：PLY、BIN、实例 JSON 和运行 JSON 均生成且可重新读取。
5. 映射测试：输出点数等于输入点数，抽样点的标签顺序无错位。
6. 结果测试：至少能在可视化点云中选择独立实例，并查看类别、点数和置信度。
7. 性能测试：记录总耗时和峰值显存，不预设未经实测的性能指标。

### 第二阶段验收

1. GUI 后台调用期间保持可操作，并可看到运行状态。
2. 成功结果能按实例着色；失败结果不会破坏当前数据。
3. 用户可从对象树或三维视图选择同一个实例。
4. 选中实例能进入现有 RANSAC/测量流程。
5. 导出结果包含类别、实例编号、拟合模型、尺寸、单位、置信度和残差。

## 8. 实施顺序

1. 编译并验证实例分割依赖。
2. 准备一份带真实 RGB 的室内测试点云。
3. 实现独立推理入口和统一输出格式。
4. 完成第一阶段测试并记录实际质量、显存和耗时。
5. 根据测试结果决定是否继续使用 ScanNet200 权重，或转向自有数据微调。
6. 第一阶段通过后，再实现 Qt/C++ 桥接、实例选择和精确测量。

## 9. 关键判断

LitePT 的分割边界只能用于缩小候选范围，不能直接作为施工尺寸。工程级尺寸来自经过坐标标定的点云和几何拟合，并需要残差、点密度、遮挡情况和人工复核共同判断。ScanNet200 仅作为通用室内基线；如果第一阶段实测无法稳定区分目标建筑构件，则下一项目阶段明确转为采集专用标注数据并微调模型，不在 GUI 集成阶段用规则掩盖模型能力不足。

## CloudForge 面板卡在“连接中…”——根因定位与修复

**根因**：`hackathon/cloudforge-panel/extensions/main/client/index.js` 中 `mount()` 末尾同步调用 `applyCollapsed(root)`，而 `applyCollapsed` 里 `root.querySelector('.cf-head-main')` 取到 `null` 后读 `.style` 抛 `TypeError`。异常冒泡 `applyCollapsed → mount → start → apply`。面板 DOM 在抛错前已 `appendChild`（所以可见），但 `renderData` 与 `setInterval(tick, 8000)` 都没执行 → 数据区永远停在 `mount()` 写死的“连接中…”。`.cf-head-main` 全仓只被读、从未赋值。

**排除**：不是 AGH 模块子系统 fail-closed idle。`packages/web-client/src/client-module.ts` 确认 `mod.apply(ctx, config)` 正常调用、`ctx.agnes.services` 就绪（否则手动 `window.__CF_SERVICE.call` 不可能成功）。

**改的文件**：
- `hackathon/cloudforge-panel/extensions/main/client/index.js`
  - `mount()`：标题 div 补 `className='cf-head-main'`；已挂载时 `return existing`（原裸 return → undefined）
  - `applyCollapsed()`：入口判空 + 三处查询加存在性判断
  - `start()`：新增 `window.__CF_DEBUG = {root, mount, renderData, tick, state}`；首次 renderData 包 try/catch
- `hackathon/cloudforge-panel/extensions/main/agnes.client.json`：`services` 增补 `cloudforge.preview`（原先只声明 cloudforge.report，预览按钮会被 client-module 门面拦成 unavailable）

**验证工具（留在 framework）**：
- `E:/C++/Point/agnes-harness/scripts-tmp/cf-panel-repro.mjs`（happy-dom 无头复现，复刻 client-module 注入的 ctx）
- `E:/C++/Point/agnes-harness/scripts-tmp/cf-panel-verify-debug.mjs`（调试钩子 + 收展交互）
- 修复前：`applyError=TypeError ... applyCollapsed:41`、`setIntervalCalls=[]`、body=`连接中…`、`serviceBridgeSet=true`
- 修复后：`applyError=null`、`setIntervalCalls=[8000]`、`workflowRendered=true`、收展 320↔40px 正常

**注意**：
- `__CF_DEBUG` 此前在 repo / profiles / daemon client-modules 三份副本里都不存在，用户以为已暴露 → Console 命令只会 undefined 报错。本次正式补上。
